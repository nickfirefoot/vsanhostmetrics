# What this pack installs, and how to remove it

Generated by `tools/gen_content_inventory.py` from the built pak. Do not
edit by hand.

Pack `iSDK_VsanHostMetrics` version **1.4.6**.

## What uninstalling does and does not remove

Uninstalling the pack **does remove the dashboards**. It leaves the
**views**, and there is no API to delete those, so they have to go by hand.

An earlier version of this document claimed uninstall left the dashboards
too. That was wrong: the 404s below were measured, the uninstall behaviour
was inferred from them and never tested. Corrected from an actual
uninstall.

| interface | result |
|---|---|
| uninstalling the pack | **removes the dashboards**; leaves the views |
| uninstall hook in the pak format | none exists; only install-time scripts |
| `GET /suite-api/api/dashboards` | 404 |
| `GET /suite-api/internal/dashboards` | 404, with the unsupported-API header |
| `GET /suite-api/api/views`, `/api/viewdefinitions` | 404 |
| `GET /suite-api/api/reportdefinitions` | 200, but contains none of ours |

Since 1.4.6 every view title ends in **`[VHM]`**, so one search of the
Views list finds exactly this pack's 30 and nothing else. Searching for
`vSAN` is not enough -- the built-in vSAN management pack's views match
that too.

The marker carries no version on purpose: view identity is a uuid5 of the
title, so a version in the name would rename all 30 every release and
leave the old ones behind. It says which pack, not which build.

Since 1.4.5 every id is a uuid5 derived from the title, so **reinstalling
replaces rather than duplicates**. You only need this list to remove the
pack entirely, or to clear the one-off duplicates left by upgrading from
1.4.4 or earlier, whose ids were random.

## Objects

Removing the adapter instance stops collection. The OBJECTS persist until
they age out, and a reinstall before that re-adopts them because identity
is derived from vSAN uuids, not from the install. To test a genuinely
clean install, delete them explicitly:

    Administration -> Inventory -> filter adapter type VsanHostMetrics
    -> select all -> Delete

Confirm the filter returns zero before reinstalling. Skipping this step is
why an upgrade can appear to work when nothing has changed.
